# 业务引导流程

## 概述

业务引导流程是EinoDevOps助手的核心功能之一，旨在引导业务人员从想法到明确需求。通过优雅的Web界面，实现AI引导式提问和交互流程，最终通过表单进行人工确认，确保需求的准确性和完整性。

## 设计理念

业务引导流程的设计理念是"以人为本，AI赋能"。我们认为，AI应该作为业务人员的助手，而不是替代者。通过AI引导式提问，帮助业务人员思考和明确需求，但最终决策权仍然在业务人员手中。

## 用户体验设计

业务引导流程的用户体验设计遵循以下原则：

- **简洁明了** - 界面简洁，操作直观
- **引导式交互** - 通过引导式提问，帮助用户思考
- **渐进式披露** - 逐步展示信息，避免信息过载
- **人机协作** - AI与人类协作，共同完成任务
- **反馈及时** - 及时反馈，让用户了解进度

## 界面设计

业务引导流程的界面设计采用现代UI设计，包括以下页面：

### 欢迎页面

欢迎页面是用户进入系统的第一个页面，设计简洁大方，突出系统的核心价值。页面中央有一个大型的"开始"按钮，引导用户进入引导流程。

### 对话页面

对话页面是用户与AI助手进行对话的页面，采用类似聊天界面的设计，但增加了更多的引导元素。左侧是对话区域，右侧是上下文信息区域，包括当前阶段、已收集的信息等。

### 反思页面

反思页面引导用户反思想法的价值和可行性。页面设计采用卡片式布局，每个卡片包含一个反思问题，用户可以通过填写文本框或选择选项来回答问题。

### 澄清页面

澄清页面通过提问澄清用户需求。页面设计采用问答式布局，每个问题下方有文本框或选项供用户回答。问题会根据用户之前的回答动态生成，确保问题的针对性和有效性。

### AI描述转换页面

AI描述转换页面将用户需求转换为AI可理解的形式。页面设计采用对比式布局，左侧是用户原始描述，右侧是AI转换后的描述，用户可以编辑和确认转换结果。

### 确认页面

确认页面是用户确认最终需求的页面。页面设计采用表单式布局，展示所有收集到的信息，用户可以进行最终确认或返回修改。

## 交互流程

业务引导流程的交互流程如下：

1. 用户进入欢迎页面，点击"开始"按钮
2. 系统引导用户进入对话页面，开始与AI助手对话
3. AI助手引导用户进入反思阶段，帮助用户反思想法的价值和可行性
4. AI助手引导用户进入澄清阶段，通过提问澄清用户需求
5. AI助手引导用户进入AI描述转换阶段，将用户需求转换为AI可理解的形式
6. AI助手引导用户进入确认阶段，用户确认最终需求
7. 系统根据确认的需求，生成项目计划和架构建议

## 技术实现

业务引导流程的技术实现基于React前端框架和Eino后端框架。前端使用React实现优雅的Web界面，后端使用Eino实现AI引导式提问和交互流程。

### 前端实现

前端使用React框架，采用组件化设计，包括以下主要组件：

- **欢迎组件** - 实现欢迎页面
- **对话组件** - 实现对话页面
- **反思组件** - 实现反思页面
- **澄清组件** - 实现澄清页面
- **AI描述转换组件** - 实现AI描述转换页面
- **确认组件** - 实现确认页面

### 后端实现

后端使用Eino框架，采用图结构实现AI引导式提问和交互流程，包括以下主要节点：

- **对话节点** - 处理用户对话
- **反思节点** - 引导用户反思
- **澄清节点** - 引导用户澄清需求
- **AI描述转换节点** - 将用户需求转换为AI可理解的形式
- **确认节点** - 引导用户确认需求

## 示例对话

以下是一个示例对话，展示业务引导流程的交互过程：

**AI助手**：欢迎使用EinoDevOps助手！我可以帮助您从想法到上线，实现全流程自动化。请告诉我您的想法。

**用户**：我想开发一个社交媒体应用，让用户可以分享短视频。

**AI助手**：这是一个有趣的想法！让我们一起来思考一下这个想法的价值和可行性。

首先，您认为这个社交媒体应用的核心价值是什么？它与现有的短视频平台（如抖音、快手）有什么不同？

**用户**：我的应用专注于特定领域的短视频，比如编程教学，并提供代码片段的分享和运行功能。

**AI助手**：非常好！专注于编程教学的短视频平台确实有其独特价值。让我们进一步澄清一些细节：

1. 您希望支持哪些编程语言？
2. 用户如何在平台上运行代码？
3. 您计划如何处理代码安全性问题？

**用户**：1. 初期支持Python、JavaScript和Go语言。
2. 使用WebAssembly在浏览器中运行代码。
3. 使用沙箱环境和代码审核机制确保安全。

**AI助手**：非常清晰的回答！根据您提供的信息，我将其转换为更结构化的需求描述：

```
项目名称：CodeShorts - 编程教学短视频平台

核心功能：
1. 用户可以上传、分享编程教学短视频
2. 支持Python、JavaScript和Go语言的代码片段分享
3. 使用WebAssembly在浏览器中运行代码
4. 提供沙箱环境和代码审核机制确保安全

技术栈：
1. 前端：React + TypeScript
2. 后端：Go语言 + Kitex RPC框架
3. 数据库：MySQL + Redis
4. 视频存储：对象存储服务
5. 代码运行：WebAssembly
```

这样的描述准确吗？您还有什么需要补充或修改的地方？

**用户**：描述很准确，但我想补充一点：平台还需要支持代码协作编辑功能。

**AI助手**：已添加代码协作编辑功能。以下是更新后的需求描述：

```
项目名称：CodeShorts - 编程教学短视频平台

核心功能：
1. 用户可以上传、分享编程教学短视频
2. 支持Python、JavaScript和Go语言的代码片段分享
3. 使用WebAssembly在浏览器中运行代码
4. 提供沙箱环境和代码审核机制确保安全
5. 支持代码协作编辑功能

技术栈：
1. 前端：React + TypeScript
2. 后端：Go语言 + Kitex RPC框架
3. 数据库：MySQL + Redis
4. 视频存储：对象存储服务
5. 代码运行：WebAssembly
6. 协作编辑：Operational Transformation算法
```

请确认这是您想要的需求描述。确认后，我将为您生成项目计划和架构建议。

**用户**：确认无误，请生成项目计划和架构建议。

**AI助手**：非常好！我将基于确认的需求，为您生成项目计划和架构建议。请稍等...
